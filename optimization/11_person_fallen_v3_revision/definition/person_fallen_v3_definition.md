# `person_fallen` v3.0 业务定义

## 版本身份

- `event_name=person_fallen`
- `event_definition_version=v3.0`
- 业务显示名：`人员异常近地姿态`
- 兼容显示名：`人员倒地`
- 模态：`image-first`
- 任务：判断是否存在需要机器人关注的异常近地人体姿态。

本文件是 v3.0 的新定义修订，不修改、回写或重解释 v2.0 的定义、历史指标、冻结结果或 Holdout 状态。v3.0 的判断对象是图像中当前可见的人体姿态和清晰可见的场景语境，不推断真实摔倒过程、受伤、昏迷、意识状态或原因。

## 正类 `positive`

满足以下任一项，且能确认是现实中的人：

- 明显仰卧、侧卧、俯卧在地面或其它非正常休息支撑面上；
- 躯干/骨盆整体大致由地面支撑，呈水平倒伏、蜷曲或异常大面积近地姿态；
- 在走廊、道路、车间、仓库等非休息区域蜷曲或躺卧；
- 爬行，包括四点支撑、手膝支撑等 crawling 姿态；
- 俯卧撑、平板支撑等由手/脚/膝主动支撑的近地姿态；
- 其它明显异常、身体大部分接近地面的支撑姿态；
- 明显俯卧或近地，但没有清晰的维修、施工、安装语境。

v3.0 不要求画面显示“正在摔倒”、受伤、失去平衡或失去意识；即使是主动躺下、训练姿态或爬行，只要落入上述可见姿态定义，仍为正类。

## 负类 `negative`

- 站立、正常行走；
- 椅子上的正常坐姿；
- 正常地面坐姿；
- 蹲、深蹲、半蹲；
- 跪、半跪；
- 弯腰、捡拾；
- 正常设备检查；
- 明确的维修、施工、安装活动；
- 床、沙发、躺椅等正常休息支撑面上的正常躺卧；
- 能明确确认不是现实中人的对象，例如清晰可辨的假人、人体海报、屏幕/镜面/照片中的人物。

“明确的维修/施工/安装”必须有可见工具、设备、对象、动作、材料或清晰的人与作业对象关系作为语境证据；人只是靠近设备，不能单独作为负类依据。

## 不确定 `uncertain`

仅在下列信息缺失导致无法确认现实中的人或无法判定可见姿态时使用：

- 人太小；
- 严重遮挡或严重模糊；
- 只看到局部身体；
- 无法确认是否为现实中的人，或无法确认关键支撑关系。

不能因为无法区分“摔倒”和“爬行/俯卧撑/平板支撑”而给出 `uncertain`，因为这些姿态在 v3.0 都属于正类。清晰可辨的假人、海报、屏幕或镜面人物不是“不确定”，而是负类。

## 决策优先级

当语境或姿态描述同时出现时，按以下顺序执行：

1. 不能确认现实中的人：`uncertain`；
2. 清晰的床/沙发正常支撑：`negative`；
3. 清晰的维修/施工/安装：`negative`；
4. 躺卧、俯卧、爬行、俯卧撑、平板支撑、地面支撑、蜷曲：`positive`；
5. 坐、跪、深蹲/半蹲、弯腰：`negative`；
6. 站立、行走或其它正常活动：`negative`。

## v3.0 真值与使用边界

v3.0 新增合成评测使用的真值类型为 `GT_TYPE=PROMPT_DERIVED_SYNTHETIC_GT`，来源为冻结的生成 prompt 和 planned role：`GT_SOURCE=FROZEN_GENERATION_PROMPT_AND_PLANNED_ROLE`。它仅用于 AI-generated 的 development、screening 和 synthetic validation；它不是 human-reviewed GT，也不是 `robot_direct` production GT。

模型预测不得生成或修正 ground truth。逐图人工语义 review 不再是 v3.0 的硬门槛：`HUMAN_SEMANTIC_REVIEW_REQUIRED=false`。旧 review package 保留为 v2 历史证据，并由 v3.0 的 supersession notice 标明不再作为 v3.0 的硬门槛。
